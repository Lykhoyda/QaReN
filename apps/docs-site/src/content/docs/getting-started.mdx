This page describes the published rn-dev-agent 1.x plugin. For the QaReN
development checkout, use the [CLI build and usage guide](https://github.com/Lykhoyda/rn-dev-agent/blob/develop/packages/qaren-cli/README.md).

## Requirements

| Requirement | Notes |
|-------------|-------|
| Node.js >= 24 | For the CDP bridge MCP server; every later major is supported |
| Claude Code, Codex, or Cursor | Use the host agent you want to run rn-dev-agent from |
| iOS Simulator or Android Emulator | At least one platform |
| Session-bound Metro | Setup previews the project integration; literal `pnpm ios` or `pnpm android` starts or validates the allocated Metro |

**maestro-runner `>= 1.1.28`** is installed into rn-dev-agent's versioned pin-cache as attested `1.1.28` by the host setup workflow. Claude's SessionStart hook only verifies the pin-cache offline and prints the explicit pinned install command when remediation is needed. In Codex, invoke `$rn-dev-agent:setup`; after its read-only diagnosis, setup converges and verifies that attested runner before previewing project changes for consent. Replay never resolves from PATH, `~/.maestro-runner`, or brew Maestro. Device control ships in-tree through the iOS/Android runners. Use the matching host setup workflow for guided remediation.

## Installation

Jump to your host: **[Claude Code](#claude-code)** · **[Cursor](#cursor)** · **[Codex](#codex)** — or [keeping up to date](#keeping-up-to-date) if it's already installed.

### Claude Code

From inside Claude Code:

<Steps>

1. Add the marketplace:

   ```bash
   /plugin marketplace add Lykhoyda/rn-dev-agent
   ```

2. Install the plugin:

   ```bash
   /plugin install rn-dev-agent@rn-dev-agent
   ```

3. Reload plugins to activate:

   ```bash
   /reload-plugins
   ```

</Steps>

### Cursor

Install the published rn-dev-agent release from **Customize → Plugins**.

Claude SessionStart hooks are not loaded (`No plugin hooks` is expected).
Requires Node.js >= 24. Reload the window after install if MCP does not appear.

**Limitation: the Cursor Plugin spawn does not bind the exact app.** rn-dev-agent
binds source identity from the supervisor's working directory and keys its process
lock on `CLAUDE_USER_CWD` or that directory. Cursor does not document a working
directory for plugin MCP servers, and the observed spawn starts from the user home,
so the lock is keyed on the home directory and source authority for the open app
is unavailable. Consequences:

- One rn-dev-agent server per user across Cursor windows. A second window refuses
  with exit code 11 and names the owner; use that session or quit it. The lock is
  not bypassed for Cursor.
- Device and proof work for an exact app checkout uses the project-rooted host
  workflow: `claude` or `codex` started in the app root. A project-scoped
  `.cursor/mcp.json` in the app checkout only helps if Cursor starts that server
  from the workspace folder, which Cursor does not document and this project has
  not verified.

### Codex

Install from the marketplace (recommended):

```bash
codex plugin marketplace add Lykhoyda/rn-dev-agent
codex plugin add rn-dev-agent@rn-dev-agent --json
```

The published 1.x release uses the same plugin payload for all hosts. The installed
plugin is fully self-contained (one bundled MCP runtime, native runner sources,
workflow helpers, health program, and runner manifest); Codex selects its own
surface from it through `.codex-plugin/plugin.json`.

Codex does not load Claude Code hooks. If the detail screen says `No plugin
hooks`, that is expected. Codex exposes the `cdp` MCP server, eleven domain skills,
and seventeen explicit workflow skills (28 total):

```text
$rn-dev-agent:setup
```

Codex 0.145.0 is the live-refresh floor. Older hosts are restart-only. A
same-app install/enable can update a subsequent turn; external CLI/manual
changes require exiting and relaunching Codex. `/mcp verbose` inspects inventory
only.

Codex setup first runs multi-axis read-only health, then manages a sentinel-
bounded `AGENTS.md` block and other project wiring only after preview/consent.
Claude setup continues to manage `CLAUDE.md`.

### Keeping up to date

Enable auto-update in the host plugin manager. Manual update:

```text
Claude: /plugin update rn-dev-agent@rn-dev-agent
        /reload-plugins
Cursor: Customize → Plugins, then Developer: Reload Window
Codex:  codex plugin marketplace upgrade rn-dev-agent
        codex plugin add rn-dev-agent@rn-dev-agent --json
        # relaunch after this external mutation
```

## Setup for your app

### No setup needed for most apps

The plugin connects to your running app via Metro's CDP endpoint and reads the React fiber tree directly.

### Zustand stores (one bridge call)

Run the matching setup workflow (`/rn-dev-agent:setup` in Claude or Cursor, or
`$rn-dev-agent:setup` in Codex) to scaffold `.rn-agent/dev-bridge.ts` and
`.rn-agent/globals.d.ts`. Then add a single registration call alongside your
store definitions:

```typescript
// App.tsx or app/_layout.tsx
import { getBridge } from './.rn-agent/dev-bridge';

getBridge()?.registerStores({
  auth: useAuthStore,
  cart: useCartStore,
});
```

No `__DEV__` guard at the call site — `getBridge()` returns `null` in production and the optional chain is a no-op. Zero production cost. The bridge handles the dev-only global assignment internally.

Both setup workflows preview this edit and ask before applying it.

### Redux

Auto-detected. No setup needed.

### testIDs

Add `testID` to interactive elements for reliable component queries:

```tsx
<Pressable testID="checkout-button" onPress={handleCheckout}>
  <Text testID="cart-badge">{itemCount}</Text>
</Pressable>
```

## Project instructions: let setup manage the host-owned file

- Claude `/rn-dev-agent:setup` manages the rn-dev-agent block in `CLAUDE.md`.
- Codex `$rn-dev-agent:setup` manages only the sentinel-bounded rn-dev-agent
  block in `AGENTS.md`; it never changes Claude instruction files.

Both paths preview changes for confirmation and are idempotent: re-running setup
skips an in-sync managed block and existing scaffold files.

Inspect the [Claude template](https://github.com/Lykhoyda/rn-dev-agent/blob/main/CLAUDE-MD-TEMPLATE.md)
or the [Codex AGENTS.md template](https://github.com/Lykhoyda/rn-dev-agent/blob/main/packages/codex-plugin/src/AGENTS-MD-TEMPLATE.md)
before running setup.

## Your agent's saved flows live in `.rn-agent/`

The plugin's home in your project is `.rn-agent/`. Saved actions, the UI skeleton,
navigation graph, and runtime state all live there. The matching setup workflow
scaffolds the directory; [`doctor`](/rn-dev-agent/commands/doctor/) reports on
its health.

See the [Actions guide](/rn-dev-agent/actions/) for what an action is, how to record one, and how the agent uses them.

## First run

Navigate to your React Native project and start building:

```bash
cd /path/to/your-rn-app
claude # or: cursor / codex
```

Claude's SessionStart hook auto-detects the project and prepares supported
dependencies. Cursor and Codex do not load Claude plugin hooks. For any host,
invoke its setup workflow when onboarding is incomplete:

```text
Claude / Cursor: /rn-dev-agent:setup
Codex:  $rn-dev-agent:setup
```

Claude walks its prerequisite checks and retries supported installations. Codex
runs passive multi-axis health and recommends user-confirmed recovery without
executing it. Both preview project wiring before writing. Once setup is ready:

```text
Claude / Cursor: /rn-dev-agent:rn-feature-dev add task priority levels with color coding and sort
Codex:  $rn-dev-agent:rn-feature-dev add task priority levels with color coding and sort
```

The plugin handles the rest — 8 phases from understanding to verified code with proof screenshots.

Want to watch it work? The [observability web UI](/rn-dev-agent/commands/observe/)
autostarts with the session. Invoke the matching `observe` workflow to get the
URL and follow the live tool-call timeline, device mirror, and app-state panels
in your browser.
