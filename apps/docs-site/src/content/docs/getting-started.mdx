## Requirements

- An Apple silicon Mac with Xcode.
- Node 24 or newer, with Corepack.
- Rust and Cargo from [rustup.rs](https://rustup.rs), for the source install below.
- `pnpm` on `PATH`; with Corepack, `corepack enable pnpm` provides it.
- An Expo app that uses `expo-dev-client` and pnpm, with a `pnpm-lock.yaml`.

Setup prepares an iOS simulator. To check on a booted Android emulator instead, see
[Check a plan](../check/).

## Install

For plugin installation and the matching release download, follow the
[root README](https://github.com/Lykhoyda/QaReN#set-up-qaren).

For an unreleased build or when the matching release asset is unavailable, install
from a checkout of the [repository](https://github.com/Lykhoyda/QaReN):

<Steps>

1. Clone the checkout and install `qaren` from it:

   ```sh
   git clone https://github.com/Lykhoyda/QaReN.git qaren-src
   cd qaren-src
   bash scripts/install-qaren-from-source.sh
   ```

   The installer builds the runtime tarball as version `<plugin version>-dev.<commit>`,
   verifies it against a manifest it writes for that build, and unpacks it under
   `~/.qaren/runtime/<version>-dev.<commit>/`, beside any released install. It prints the
   installed binary path, and `qaren --version` names the commit. A source build always
   builds its iOS runner from source.

2. From your app's root directory, start Claude Code with the checkout's plugin:

   ```sh
   claude --plugin-dir <checkout>/packages/qaren-plugin
   ```

   `<checkout>` is the absolute path of `qaren-src`.

3. Run the setup skill:

   ```text
   /qaren:setup
   ```

</Steps>

### Where `qaren` lands on PATH

The installer links `qaren` into a directory on your `PATH`:

1. The first of `~/.local/bin`, `~/bin`, `/opt/homebrew/bin` and `/usr/local/bin` that is
   on `PATH`, exists and is writable. An earlier IDE or toolchain directory is passed over.
2. Otherwise, the first writable absolute directory on `PATH`. Empty and relative entries
   are skipped.
3. Otherwise, it links `~/.local/bin/qaren` and prints the line to run:

   ```sh
   export PATH="$HOME/.local/bin:$PATH"
   ```

It never edits shell startup files. When `PATH` already holds a `qaren`, the installer
considers only the first one, so it never adds a second link that hides it. It replaces
that link only when it points into the same QaReN home and the same line: a release
replaces a release, and a source build replaces a source build. A link to another
`QAREN_HOME`, or a working link of the other line, is kept with a notice; pass `--link`
to replace it. Any other `qaren` file is left alone with a notice. A link problem never
fails the install: run `qaren` by the binary path the installer printed. Re-run the
installer to recover an interrupted install.

### Run a release and a source build side by side

`QAREN_HOME` moves everything QaReN keeps per user (runs, state, installed runtimes and
the runner cache) from `~/.qaren` to another absolute directory whose parent exists.
Device locks and the native build cache stay machine-wide, so a release install and a
source build in different homes still refuse each other's simulators:

```sh
export QAREN_HOME=/path/to/dev-home/.qaren
bash scripts/install-qaren-from-source.sh
"$QAREN_HOME/runtime/<version>-dev.<commit>/bin/qaren" doctor
```

Keep `QAREN_HOME` set for every command that uses that install; `qaren doctor` names the
home in use.

## What `/qaren:setup` does

Setup runs six steps from the app's root directory. When a step stops, it gives the one
reason and the fix.

1. **CLI.** It verifies or installs the plugin's matching `qaren` runtime; follow the
   [installation contract](https://github.com/Lykhoyda/QaReN/blob/main/packages/qaren-cli/README.md#plugin-runtime-installation)
   for verification, PATH linking and the source fallback.
2. **App.** It checks that `package.json` lists `expo` and `expo-dev-client` and that
   `pnpm-lock.yaml` exists. It asks before running `pnpm install`. It reads the bundle
   identifier and the app's `slug` from `pnpm exec expo config`; when that fails, it asks
   you for both values rather than guessing.
3. **Config.** It writes `.qaren/config.yaml`:

   ```yaml
   appId: <bundle identifier>
   devClientScheme: exp+<slug>
   ```

   `exp+<slug>` is the scheme `expo-dev-client` generates. When the app's config turns that
   scheme off, setup asks you for the scheme the app registers instead. An existing config
   is shown next to the detected values and changed only with your consent. See [Configuration](../configuration/) for every key.
4. **Device.** It reads the simulator inventory and never boots, shuts down or erases a
   simulator itself. With one booted simulator it passes no device flag. With none, it
   picks the newest available iPhone and passes `--boot-device --device <udid>`, so
   `qaren` boots it under its device lease. With several, it asks you which one.
5. **Smoke plan.** It reads the app's launch path in source, picks a text shown on the
   first screen, and writes `.qaren/plans/smoke.md`. This plan needs no
   `TYPESAFE_API_KEY`.
6. **Run.** It starts the first `qaren check` detached, because a cold native build can
   take longer than the host's command limit, and follows the run until it ends. Within a
   minute the progress log names the run, and you can watch it in your own terminal with
   `qaren watch <run-id>`. It then reports the receipt's `result`, `run_id` and
   `next_action`.

On `pass`, QaReN is set up. If the receipt's `next_action` is a `qaren cleanup` command,
teardown was incomplete and setup offers to run it.

## First check

Setup writes the smoke plan in this shape, with the text it picked from your first screen:

```md title=".qaren/plans/smoke.md"
## QA

### First screen

1. Wait for "<text>" to appear
✓ "<text>"
```

Run it again yourself from the app's root directory, on the simulator setup used:

```sh
qaren check --plan-file .qaren/plans/smoke.md --device <udid> --json
```

`<udid>` is the simulator setup chose or booted. With exactly one booted simulator you can
leave `--device <udid>` out; with several, `qaren check` refuses without it.

Follow it from a second terminal:

```sh
qaren watch --latest
```
