Once [setup](../getting-started/) has passed, ask your agent in plain words. The plugin's
skills tell it what to run; none of them drives a device directly.

| Ask your agent         | What it does                                                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| "QA this feature"      | Picks a saved plan or writes one from the feature's screens in source, then runs it on your working tree.                                             |
| "QA PR #12"            | Runs the plan at the pull request's head. It posts the result to the pull request only when you ask, after you confirm the plan and recording may be posted. |
| "Follow the run"       | Follows the latest run live.                                                                                                                          |
| "Report a QaReN bug"   | Drafts a sanitized GitHub issue about QaReN, shows it in full, and files it only after you confirm.                                                    |

## What comes back

A verdict (PASS, FAIL, or a refusal that says what to fix); a report with one line per step and
screenshots; on a pull request, a comment with the verdict, the tested commit, the plan lines
and the video when it can be published.

To read what the agent wrote or ran, see [Write a plan](../plans/),
[Test a pull request](../pull-requests/) and [Saved blocks](../saved-blocks/).

## Skills

The `qaren` plugin teaches a coding agent to drive the `qaren` CLI. It ships three skills.
Each one runs the CLI; none of them drives a device directly.

| Skill         | Claude Code name    | Use it to                                                                                                           |
| ------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `setup`       | `/qaren:setup`      | install `qaren` onto PATH, write `.qaren/config.yaml`, pick the simulator and run a first smoke check. See [Getting started](../getting-started/). |
| `using-qaren` | `/qaren:using-qaren` | write a plan for a feature, then run [`qaren check`](../cli/#qaren-check) on the working tree or [`qaren pr`](../cli/#qaren-pr) on a pull request, and report the receipt. |
| `feedback`    | `/qaren:feedback`   | draft a sanitized GitHub issue about QaReN, show it in full, and file it only after you confirm.                   |

Codex and Cursor invoke the same skills with their own syntax. In Claude Code, Codex or
Cursor, you can also ask in plain words, such as "QA this pull request with QaReN"; the
agent picks the matching skill from its description. Install steps for each host are in the
[root README](https://github.com/Lykhoyda/QaReN#set-up-qaren).

## Hosts

The plugin folder carries one manifest per host. Each manifest decides what that host
loads.

| Host        | Manifest                        | What it loads                                                                                                    |
| ----------- | ------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Claude Code | `.claude-plugin/plugin.json`    | The three skills it lists, and the SessionStart hook in `hooks/hooks.json`.                                      |
| Codex       | `.codex-plugin/plugin.json`     | Every skill under `skills/`.                                                                                     |
| Cursor      | `.cursor-plugin/plugin.json`    | Every skill under `skills/`, found in its default folder. The manifest sets hooks empty, so no SessionStart hook. |

The SessionStart hook only verifies the installed runtime. It prints the verified binary
path or the command to install or repair it, and it never downloads.

## Feedback

`/qaren:feedback` gathers `qaren --version`, the macOS, Xcode and Node versions and, for a
report about a run, the receipt's `result`, `run_id`, `failure.code` and
`failure.next_action` with the run's `report.md`. It leaves out the run's media and
screenshots, plan text with typed values and the values in `.qaren/config.yaml` unless you
ask for them. It files the issue with `gh` only after you confirm the exact draft.
