Claude Code, Codex or Cursor writes the React Native change. QaReN tries it in your app on an
iOS simulator and comes back with PASS or FAIL, and the evidence behind it.

## Your agent says it is done. Did anyone open the app?

A coding agent checks its work the ways it can: types, lint, unit tests. It does not tap
through the app. A screen that never appears, a tap that lands on nothing or a flow that
breaks halfway gets past all of those and reaches review, or your users.

QaReN is the QA engineer on your agent's team. Your agent hands it the change and a short
plan of what to check; QaReN runs that plan in the real app and tells both of you what
happened.

## What a check looks like

1. You ask your agent to QA a change, for example "QA the onboarding change".
2. The agent writes a plan in Markdown: what to tap, what to wait for and what must be on
   screen.

   ```md
   ### Onboarding to the tasks tab

   1. Tap "onboarding-skip"
   2. Wait for "Welcome" to appear
   ✓ "Welcome"
   3. Tap "tab-tasks"
   ```

3. QaReN borrows a simulator, builds and installs the app from your working tree, starts
   Metro, walks the plan step by step and tears down what it started.
4. You get PASS or FAIL with the evidence. On a pull request, QaReN can record the screen
   and post the result as a comment.

## Why you can trust the verdict

### A verdict, not a summary

Every run ends in PASS, FAIL or a refusal with a typed reason and the next action to take.
Your agent reads it as JSON; your scripts read the exit code.

exit 0 pass · 1 fail · 4 refused

### Evidence you can open

Each run keeps a step-by-step ledger and a readable report at the paths its receipt names.
A pull request run adds a screen recording when one can be captured.

report.md · ledger.json · run.json · logs/events.jsonl

### It tests what you changed

QaReN builds your working tree, or a pull request's head, and fails the run if the code
changes while the plan is being walked, so a drifted run can never pass.

CANDIDATE_DRIFTED is never a pass

### Faster on every run

A passing block that is eligible is saved under `.qaren/actions/` and replayed next time by
the exact elements it used, so repeat checks skip the search.

ledger.blocks: replayed · patched · discovered

## Built for

- **Coding agent:** Claude Code, Codex or Cursor, through the QaReN plugin.
- **App:** an Expo React Native app that uses `expo-dev-client` and pnpm.
- **Mac:** an Apple silicon Mac with Xcode. QaReN 2.0 sets up and checks on an iOS simulator.
- **Android:** coming in 2.1.
