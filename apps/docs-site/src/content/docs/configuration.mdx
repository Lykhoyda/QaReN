Your agent writes and runs this; here is what it means.

`qaren check` and `qaren pr` read `.qaren/config.yaml` from the directory they run in;
`--config <path>` selects another file. Unknown keys are rejected; the refusal
[states what it found](#when-the-file-is-refused).

```yaml
appId: com.example.testapp
devClientScheme: testapp
metroPort: 8791
loginBlock: sign-in
loginMarker:
  id: login-screen
```

## Keys

| Key               | Type             | Default | Meaning                                                                                       |
| ----------------- | ---------------- | ------- | --------------------------------------------------------------------------------------------- |
| `appId`           | string           | —       | Required. The app's bundle ID on iOS or package name on Android.                              |
| `devClientScheme` | string           | —       | Required for `check` and `pr`. The app's registered dev-client URI scheme, 1–128 bytes matching `[A-Za-z][A-Za-z0-9+.-]*`. |
| `video` | `strict` or `non-strict` | dev mode (non-strict rules) | Screenshot and video privacy policy; see [video](#video). |
| `packageManager`  | string           | `pnpm`  | The app's package manager. Only `pnpm` is supported.                                          |
| `metroPort`       | integer          | `8791`  | The port of the Metro server the run starts. At least `1024`.                                 |
| `nodePath`        | string           | `node` on `PATH` | An absolute path to the Node binary to use. It must be Node 24 or newer.             |
| `registryAuthEnv` | list of strings  | `[]`    | Names, never values, of extra environment variables kept for private-registry auth; see the [registry-auth scope and output policy](https://github.com/Lykhoyda/QaReN/blob/develop/packages/qaren-cli/README.md#plan-checks-and-screen-evidence). |
| `loginBlock`      | string           | —       | The slug of a saved block that signs in; see [login recovery](../saved-blocks/#login-recovery). |
| `loginMarker`     | object           | —       | What shows the login screen: exactly one non-empty `id` (a `testID`) or `text` (a label).     |
| `savePlans`       | boolean          | `true`  | Whether `check` saves fully passing plans into `.qaren/plans/` and flags or clears saved plans; see [saved plans](../plans/#saved-plans). |
| `proofInDescription` | boolean       | `false` | Opt in to the [description publication contract](../pull-requests/#the-description). |
| `depsCache` | boolean | `true` | Dependency reuse for `pr`; see the [cache contract and cold-run switch](https://github.com/Lykhoyda/QaReN/blob/develop/packages/qaren-cli/README.md#test-a-pull-request). |
| `ios`             | object           | —       | iOS settings, below.                                                                          |
| `android`         | object           | —       | Android settings, below.                                                                      |
| `build`           | object           | See below | Native build priority and worker cap; see [build](#build).                                  |
| `deadlines`       | object           | See below | Preparation budgets; see [deadlines](#deadlines).                                           |

`loginBlock` and `loginMarker` are set together. `loginBlock` must be an action slug: it
starts with a letter or digit, then letters, digits, `_`, `.` or `-`, at most 64 characters,
without `..`.

## `ios`

| Key               | Type   | Meaning                                                                    |
| ----------------- | ------ | -------------------------------------------------------------------------- |
| `deviceType`      | string | Accepted, but not used by `check` or `pr`, which borrow a booted simulator. |
| `runtime`         | string | Accepted, but not used by `check` or `pr`.                                 |
| `build.workspace` | string | An existing `ios/*.xcworkspace`, relative to the app directory.            |
| `build.scheme`    | string | The Xcode scheme to build in that workspace, 1–256 bytes.                  |

By default the iOS build uses the app's Expo CLI in generic build-only mode. Older Expo CLIs
lack that mode: set `ios.build` with both `workspace` and `scheme` to build an existing Xcode
workspace instead.

```yaml
appId: com.example.testapp
devClientScheme: testapp
ios:
  build:
    workspace: ios/TestApp.xcworkspace
    scheme: TestApp
```

The workspace route builds Debug for the iOS Simulator with ad-hoc simulator signing. It runs no
CocoaPods or codegen step of its own, so the workspace's native dependencies must already be
ready for Xcode.

## build

Native build controls are optional. For how they are applied, environment
precedence, architecture exceptions and receipt evidence, see the
[build priority and worker cap contract](https://github.com/Lykhoyda/QaReN/blob/develop/packages/qaren-cli/README.md#native-fingerprint-build-selection).

| Key        | Type                | Default            | Meaning                                                                 |
| ---------- | ------------------- | ------------------ | ----------------------------------------------------------------------- |
| `jobs`     | positive integer    | from the machine   | Override the worker cap; see the contract above for application and precedence. |
| `priority` | `low` or `normal`   | `low`              | `normal` runs builds without `nice`.                                    |
| `arch`     | `all`               | See contract above | Turn off QaReN's architecture exclusion; see the contract above for defaults and exceptions. |

```yaml
build:
  jobs: 4
  priority: normal
```

## deadlines

Optional preparation budgets for `check` and `pr`: a native build time limit,
a dependency-install time limit, a simulator-boot time limit, a manifest warm-up
limit, and a dev-client attach limit. For registered-target deadlines, no-target
waiting and patient recovery, see the authoritative
[admission and recovery contract](https://github.com/Lykhoyda/QaReN/blob/develop/packages/qaren-cli/README.md#check-a-plan).

| Key                    | Default (seconds) |
| ---------------------- | ----------------- |
| `install_deps_seconds`  | `900`             |
| `build_seconds`         | `2400`            |
| `device_boot_seconds`  | `420`             |
| `manifest_warmup_seconds` | `420`             |
| `attach_seconds`       | `120`             |

For platform-lock and shared build-slot waiting, the iOS build window,
publication and cleanup boundaries, and Android wait budgets, follow the
[build serialization contract](https://github.com/Lykhoyda/QaReN/blob/develop/packages/qaren-cli/README.md#native-fingerprint-build-selection).
On iOS, install, launch and readiness share a fresh `build_seconds` window,
and Metro startup has a separate one.

For manifest warm-up bounds, diagnostics and the Expo offline default and override,
see the [launch readiness contract](https://github.com/Lykhoyda/QaReN/blob/develop/packages/qaren-cli/README.md#ios-simulator-lifecycle).

Each limit is a whole number of seconds from 30 through 7200 inclusive.
Omit the block, write `deadlines: {}`, or write a bare
`deadlines:` to keep every default. A field that is present overrides only
that field.

Out-of-range values are refused with `SCENARIO_INVALID`, rather than clamped.
`install_deps_seconds` also bounds the pre-run pnpm process-group probe and its retries.
A null, tilde, blank, negative, fractional, quoted, boolean, list, or object
field value is a parse refusal, as is an unknown key, a camelCase alias, or a
duplicate key. Explicit `deadlines: null` and `deadlines: ~` are also refused.
When the conditions below hold, the refusal names a misplaced or respelled
deadline key, and for any loaded file it names a deadline outside its range by
its key, but never a value of the wrong type or a key written twice; see
[when the file is refused](#when-the-file-is-refused).
`check` and `pr` store the effective budgets at `scenario.deadlines` in
`run.json`. For `pr`, these budgets come from the operator-selected
configuration, even if the candidate worktree contains different deadlines.
`prepare` keeps the deadlines in its scenario file, independently of app
configuration.

```yaml
appId: com.example.testapp
devClientScheme: testapp
deadlines:
  build_seconds: 5400
```

## When the file is refused

A file that does not load stops `check` and `pr` before the plan is read or a
device is chosen, with `SCENARIO_INVALID` (`SCENARIO_UNREADABLE` when the file
is missing or cannot be read). Key faults are stated when the file contains no
`!` and the second, untyped read of it succeeds (that read fails for a key
written twice and for a number too large to read, wherever they are in the
file); a reader stop is stated in any file, and value rules are checked in a
fixed order for any file that loads, with or without `!`, reporting the first
rule that fails. When those conditions hold, the refusal and the `config` row
of `qaren doctor` state what is wrong, without quoting the file:

| In the file | What the refusal states |
| ----------- | ----------------------- |
| `attach_seconds: 300` or `attachSeconds: 300` at the top level | the top level has a key for `attach_seconds`, which is read only under `deadlines:` |
| `attachSeconds: 300` under `deadlines:` | `deadlines:` has a key for `attach_seconds` in another spelling |
| `attach_seconds: 7201` under `deadlines:` | `deadlines.attach_seconds` is outside 30 through 7200 seconds |
| a key its block does not read | its position in its block and the `qaren` version that read the file |
| a tab used to indent, an unclosed bracket or quote | the line and column where the YAML reader stopped |

```yaml
appId: com.example.testapp
devClientScheme: testapp
deadlines:
  attach_seconds: 300
```

For a key fault the refusal states the fact, and there is one next step for
every stated parse fault, listing every key and where it is read; how to edit
the file is yours to decide. A key inside a block that is itself stated as
misplaced, respelled or unread is not looked at until that block is corrected.
At most three statements are shown; further faults are counted, not described.
Other faults keep the general refusal, which lists the keys: a missing `appId`,
a value of the wrong type such as a quoted deadline, a key written twice, a
number too large to read, and any key fault in a file that contains `!`. No
second name is read for any key, and no key has been removed, renamed or moved
since 2.0.0. For every fault class, its code and the keys added since 2.0.0,
see the
[configuration refusal contract](https://github.com/Lykhoyda/QaReN/blob/develop/packages/qaren-cli/README.md#check-a-plan).

## Environment

| Variable              | Meaning                                                                         |
| --------------------- | ------------------------------------------------------------------------------- |
| `TYPESAFE_API_KEY`    | Required by plans with phrase steps or phrase checks; see [Jev: how QaReN judges phrase steps](../jev/#key-and-readiness). |
| `ANDROID_HOME`        | The Android SDK whose `platform-tools/adb` reaches the running adb server.      |
| `QAREN_NODE`          | The Node binary to use; it takes precedence over `nodePath`.                    |
| `QAREN_HOME`          | Selects the per-user storage root; see the [storage and state lookup contract](https://github.com/Lykhoyda/QaReN/blob/develop/packages/qaren-cli/README.md#release-and-source-builds-side-by-side). |
| `QAREN_LOCK_ROOT`     | Explicit lock namespace; see the [lock-root contract](https://github.com/Lykhoyda/QaReN/blob/develop/packages/qaren-cli/README.md#ios-admission-and-cleanup) for precedence and validation. |
| `QAREN_MACHINE_LOCKS` | Machine-wide locks are on by default; `0` opts out to per-home locks; see the [lock-root contract](https://github.com/Lykhoyda/QaReN/blob/develop/packages/qaren-cli/README.md#ios-admission-and-cleanup) for safe switching. |
| `QAREN_NATIVE_CACHE_ROOT` | An exact private absolute directory for reusable iOS builds. Defaults on macOS to `/private/var/tmp/qaren-native-cache-<uid>`, shared across HOME values for that user. |
| `QAREN_WALK_SECONDS`  | The walk budget in seconds. Defaults to `1200`.                                 |
| `QAREN_STEP_SECONDS`  | The per-step budget in seconds. Defaults to `1200`.                             |
