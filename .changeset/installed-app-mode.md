`qaren check --installed-app` walks a plan on the release build already installed on the iOS simulator and leaves that build in place: QaReN does not build, install, uninstall or reconfigure the app, starts no Metro and attaches no debugger, and launches the installed app with no arguments. The receipt names the tested build (version, build number, and the sha256 of its `main.jsbundle` and executable), and the run fails with `CANDIDATE_DRIFTED` if the JavaScript changes during the walk. Strict media rules always apply, `--record` and `--fresh-install` are refused, a configured login block is not replayed, and plan lines that need the model are refused in preflight (`PLAN_UNPARSEABLE`, one entry per line) before any device command. An app that is not installed is refused with `INSTALLED_APP_MISSING`, a development build with `INSTALLED_APP_NOT_STANDALONE`, and Android with `INSTALLED_APP_UNSUPPORTED`; each refusal names the cause and a next step. In this mode a device lease held by a dead earlier run that created the simulator is refused with `DEVICE_BUSY` instead of being reclaimed, because that run's cleanup can delete the simulator.
